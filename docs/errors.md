# Журнал ошибок

## 2026-10-19

### BIG-O
- **Почему `x in set` быстрее, чем `x in list`.** Множество хранит данные в хеш-таблице, поэтому проверка O(1) в среднем. Список проверяется по очереди, это O(n). Уникальность элементов тут ни при чём.

### Git
- **Имя ветки.** `git merge` принимает имя существующей ветки. Перед слиянием проверять `git branch`.
- **Detached HEAD.** `git checkout origin/main` перевёл HEAD на коммит, а не на ветку. Вернуться: `git switch main`
- **`echo "текст" > файл` в PowerShell** пишет в UTF-16, и Git считает файл бинарным. Файл создавать в редакторе.
- **Fast-forward.** Если `main` не двигался, merge просто передвигает его вперёд без нового коммита. Нужен коммит слияния: `git merge --no-ff`.

### Английский
- Present Perfect (for/since, have/has) еще не проходил, вернуться к теме после соответствующего раздела Мёрфи.

## 2026-10-20

### BIG-O
- **Блоки подряд складываются, остаётся старший член.** O(n) + O(n^2) = O(n^2)
- **`target in set(items)` это O(n), а не O(1).** Построение множества стоит O(n), O(1) только проверка в уже готовом множестве
- **Скрытая вложенность.** `x in list`, `list.index(x)` внутри цикла дают O(n²), даже если явный цикл один.
- **Two Sum.** Для поиска пары нужно хранить число и его индекс (словарь `число -> индекс`), тогда `list.index` не нужен. 

### Приёмы
- **Two Sum.** Сначала проверяем `target - num in seen`, потом записываем `seen[num] = i`, иначе элемент найдёт сам себя.

### Git
- **Merge в процессе.** Если `git status` пишет "All conflicts fixed but you are still merging", не хватает только `git commit`. Прервать слияние можно через `git merge --abort`.
- **Граф без `--all`** показывает только историю текущей ветки, поэтому чужая ветка на нём не видна, пока её не влили.
- **Конфликт слияния.** `git merge` остановился на `CONFLICT`: открыть файл, оставить нужное, удалить маркеры `<<<<<<<`, `=======`, `>>>>>>>`, затем `git add` и `git commit`. Сделать `git status`, если не понятно, на каком шаге находишься.
- **`pip freeze` выписывает всё окружение.** Окружение нужно своё на каждый проект, иначе в `requirements.txt` попадут чужие зависимости.

## 2026-10-21

### HTTP
- **PUT идемпотентный** (замена целиком), **PATCH нет** (частичное изменение), **POST нет** (создаёт новое при каждом вызове).
- **CONNECT не идемпотентный и не безопасный.** DELETE и OPTIONS в таблицу методов тоже входят.
- **Идемпотентность считается по состоянию сервера, а не по коду ответа:** DELETE первый раз 200/204, потом 404, но состояние одинаковое.
- **curl:** `-i` (заголовки), а не `-1`; `@data.json` ищется в текущей папке.
- **`httpx.RequestError`, не `RequestException`.** Имя из `requests` в httpx не работает; ошибка вылезает только на сбое соединения.
- **`.response` есть только у `HTTPStatusError`.** У таймаута и ошибок соединения ответа нет вообще, потому что сервер не отвечал.
- **Каждая ветка `except` должна быть запущена хотя бы раз.** `NameError` из-за `as e` не проявился на тестах таймаута и Wi-Fi, а нашёлся только на коде 404.
